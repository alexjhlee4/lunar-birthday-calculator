# 음력 생일 계산기

한국에서 음력 생일을 챙기는 가족을 위해 만든 **완전 정적 한국 음력 생일 계산기**입니다. 양력 또는 음력 생년월일을 입력하면 실제 출생일을 정규화하고, 선택한 양력 연도마다 같은 음력 월·일이 양력으로 언제인지 계산합니다.

모든 계산은 브라우저 안에서만 실행됩니다. 백엔드, 데이터베이스, 외부 날짜 변환 API, 분석 서비스, 쿠키, `localStorage`를 사용하지 않습니다.

## 주요 기능

- 양력 → 한국 음력 변환
- 한국 음력 → 양력 변환
- 평달·윤달 입력과 존재하지 않는 윤달 차단
- 태어난 음력 연도 기준 연간지 표시
- 5년·10년·20년·30년 연도별 음력 생일 계산
- 윤달이 없는 해의 같은 월·일 평달 대체
- 음력 30일이 없는 작은달의 29일 자동 조정
- 실제 양력 출생일 기준 만 나이
- 월간 달력, 월 이동, 연도 이동, 오늘 이동, 직접 이동
- 결과표와 달력 양방향 연결
- 정확한 양력 연도 검색과 단일 상태 필터
- 키보드 접근, 포커스 표시, 모달 포커스 트랩, 라이브 안내
- 계산 직후 핵심 생일 날짜를 가장 먼저 보여주는 결과 우선 UX
- 입력·변환 상세, 조회 고급 설정, 달력을 필요할 때 펼치는 Progressive Disclosure
- 데스크톱 표 / 모바일 카드 반응형 결과 UI
- 오프라인 계산과 정적 배포

## 양력 입력과 음력 입력의 차이

### 양력으로 입력

공식 기록의 실제 양력 생년월일을 입력합니다. 입력 날짜를 음력으로 바꾼 뒤, 변환된 음력 월·일을 매년 반복합니다.

예: 입력 화면의 중립 예시는 양력 `1980-01-01`을 사용합니다. 실제 결과는 입력한 날짜를 한국 음력 기준으로 변환해 계산합니다.

### 음력으로 입력

가족이 기억하는 음력 생년월일을 직접 입력합니다. 입력 날짜를 태어난 해의 양력 날짜로 변환하여 실제 만 나이 계산 기준으로 사용합니다.

예: 음력 `1980-01-01 평달` → 양력 출생일 `1980-02-16` → 2026년 생일 `2026-02-17`

양력과 음력에 같은 숫자를 입력해도 서로 다른 날짜입니다.


## UX 개편 V1

이번 버전은 계산 로직을 바꾸지 않고 정보 구조를 먼저 단순화했습니다.

- 기존 `1단계 → 2단계 → 3단계 → 달력 → 4단계` 표기를 제거했습니다.
- 계산 직후 선택한 기준 연도의 양력 생일 날짜를 가장 큰 글자로 먼저 보여줍니다.
- 입력·변환 정보는 `입력·변환 정보 자세히 보기`에 접었습니다.
- 결과 목록을 달력보다 먼저 배치했습니다.
- 직접 연도 이동, 검색, 상태 필터는 `조회 설정 더보기`에 접었습니다.
- 달력은 기본적으로 접힌 보조 도구로 바꾸고, `달력에서 보기`를 눌렀을 때 자동으로 펼쳐집니다.
- 정상 상태의 `일반` 배지는 숨기고 윤달 대체·29일 조정 등 예외 상태만 강조합니다.
- 입력 예시를 `1980년 1월 1일`로 통일했습니다.
- 외부 CSS가 일시적으로 로드되지 않아도 화면이 완전히 무너지지 않도록 `index.html`에 최소 critical fallback 스타일을 포함했습니다. 다만 프로젝트 기능 전체를 사용하려면 `css/`, `js/`, `vendor/` 폴더를 포함한 프로젝트 전체가 함께 배포되어야 합니다.

## 실행 방법

### 권장: VS Code Live Server

1. 이 프로젝트 폴더를 VS Code로 엽니다.
2. VS Code 확장 프로그램에서 **Live Server**를 설치합니다.
3. `index.html`을 우클릭합니다.
4. **Open with Live Server**를 선택합니다.
5. 테스트는 `tests/test-runner.html`을 Live Server로 엽니다.

### 파일 직접 열기

이 프로젝트는 ES Module이나 `fetch()` 없이 일반 스크립트로 구성되어 있어 대부분의 최신 브라우저에서 `index.html`을 직접 열어도 작동합니다. 브라우저 보안 정책이나 확장 프로그램 때문에 로컬 스크립트 실행이 제한되면 Live Server를 사용하세요.

### Upstream 지원 범위

### 이 서비스의 지원 범위

제품 요구사항에 따라 UI·입력·결과·달력은 다음 범위로 더 엄격히 제한합니다.

- 최소: `1900-01-01`
- 최대: `2050-12-31`

음력 입력은 숫자만 보고 상한을 결정하지 않습니다. 실제 음력→양력 변환에 성공하고 변환 결과가 위 양력 범위 안에 있는지 다시 검사합니다.

## 계산 기준

### 결과의 연도

결과의 “2026년”은 양력 `2026-01-01`부터 `2026-12-31` 사이에 발생하는 음력 생일을 뜻합니다. 각 양력 연도에 대해 인접한 음력 연도를 함께 검사하고, 변환된 양력 날짜가 실제 대상 양력 연도에 포함될 때만 결과에 넣습니다.

기간 5년은 기준 연도를 포함한 총 5개 양력 연도입니다.

```text
기준 2026년 + 5년
→ 2026, 2027, 2028, 2029, 2030
```

2050년을 넘는 기간은 2050년까지만 표시하고 범위 제한 안내를 보여줍니다.

### 윤달 입력 검증

출생 날짜 입력에서 윤달을 선택했는데 해당 음력 연도에 그 윤달이 없으면 계산을 중단합니다. 평달로 임의 변경하지 않습니다.

### 윤달생의 연도별 대체

- 대상 음력 연도에 같은 윤달이 있으면 원래 윤달 날짜 사용
- 같은 윤달이 없으면 같은 월·일의 평달로 대체
- 결과에 `평달로 대체` 상태와 설명 표시

### 작은달의 음력 30일

대상 월이 29일까지인 작은달이면 음력 30일을 그달의 마지막 날인 음력 29일, 즉 그믐으로 자동 조정합니다.

윤달 대체와 29일 조정이 모두 필요하면 다음 순서로 처리합니다.

1. 윤달이 없으므로 평달로 대체
2. 대체된 평달이 작은달이면 30일을 29일로 조정

두 상태 코드와 두 설명을 모두 보존합니다.

### 실제 만 나이

- 양력 입력: 입력한 양력 날짜가 실제 출생일
- 음력 입력: 태어난 해의 음력 날짜를 변환한 양력 날짜가 실제 출생일
- 각 결과 날짜와 실제 양력 출생일의 월·일을 비교하여 계산

2월 29일 출생자는 제공된 날짜 비교 규칙에 따라 비윤년에는 3월 1일부터 나이가 증가합니다.

### 태어난 해의 간지

양력 숫자 연도를 그대로 쓰지 않고 변환된 음력 생년월일의 음력 연도를 기준으로 연간지만 표시합니다.

표시 예: `계묘년(癸卯年)`

월간지, 일간지, 시간 간지, 사주, 운세, 띠 해석은 제공하지 않습니다.

## 날짜와 시간대 안전성

핵심 날짜 계산에는 `new Date("YYYY-MM-DD")` 또는 `toISOString().split("T")[0]`를 사용하지 않습니다.

- 날짜 객체는 `new Date(year, month - 1, day, 12, 0, 0)`으로 생성
- 날짜 키는 숫자 구성요소를 직접 이어 `YYYY-MM-DD`로 생성
- 정오를 사용하여 DST·UTC 경계에서 날짜가 하루 밀릴 가능성을 줄임

## 상태 코드

문구 비교로 로직을 처리하지 않고 다음 상태 코드를 사용합니다.

```js
NORMAL
LEAP_ORIGINAL
LEAP_TO_REGULAR
DAY_30_TO_29
LEAP_TO_REGULAR_AND_DAY_30_TO_29
```

복합 조정 결과는 원인 상태 배열에 `LEAP_TO_REGULAR`, `DAY_30_TO_29`를 모두 저장하고, 필터용 복합 상태 코드도 별도로 계산합니다.

## 테스트

`tests/test-runner.html`은 실제 vendor 라이브러리와 서비스 모듈을 브라우저에서 불러와 각 항목을 `PASS` 또는 `FAIL`로 표시합니다.

검증 항목:

1. 양력 1980-01-01 → 음력 1979-11-14, 기미년. 2026년에는 같은 음력 월·일이 양력 연도 안에 두 번 포함되는 케이스도 검증
2. 음력 1980-01-01 평달 → 양력 1980-02-16, 2026-02-17, 만 46세
3. 존재하지 않는 윤달 입력 차단
4. 윤달생의 평달 대체
5. 음력 30일의 29일 조정
6. 윤달 대체 + 29일 복합 조정
7. 1900-01-01 / 2050-12-31 경계와 범위 밖 차단
8. 월 이동과 최소·최대 달력 경계
9. 로컬 날짜 구성요소와 날짜 키
10. 결과→달력, 달력→결과 상태 연결
11. 연도 검색과 모든 상태 필터
12. 생일 전·당일·후, 음력 입력, 2월 29일 만 나이

## 정상 동작 확인 순서

1. `tests/test-runner.html`에서 12개 항목이 모두 PASS인지 확인합니다.
2. 양력 모드에 `1980 / 1 / 1`을 입력합니다.
3. 변환된 음력 날짜가 `1979년 11월 14일 · 평달`인지 확인합니다.
4. 2026년에는 `2026년 1월 2일`과 `2026년 12월 22일` 두 결과가 모두 표시되는지 확인합니다.
5. 음력 모드에 `1980 / 1 / 1`, 평달을 입력합니다.
6. 양력 출생일이 `1980년 2월 16일`인지 확인합니다.
7. 2026년 결과가 `2026년 2월 17일`, `만 46세`인지 확인합니다.
8. 결과의 **달력에서 보기**를 눌러 달력 이동·선택·상세 정보가 연결되는지 확인합니다.
9. 달력의 생일 셀을 눌러 결과 행 강조와 **결과에서 보기** 버튼을 확인합니다.
10. 키보드 `Tab`, `Shift+Tab`, `Enter`, `Escape`로 입력·달력·모달을 조작합니다.

## 알려진 제한 사항

- 서비스 지원 범위는 `1900-01-01`~`2050-12-31`입니다.
- 한국 음력 기준만 지원합니다. 중국·베트남 등 다른 지역 음력은 지원하지 않습니다.
- 윤달생이 같은 윤달이 없는 해에는 서비스 정책상 같은 월·일의 평달을 사용합니다.
- 작은달의 음력 30일은 서비스 정책상 음력 29일로 앞당깁니다.
- 생년월일, 계산 결과, 사용자 설정을 저장하지 않습니다.
- 음력 생일 알림, 계정, 공유 링크, 서버 동기화는 포함하지 않습니다.
- 법률·행정 목적의 공식 증명 자료가 아니라 가족 생일 확인을 돕는 도구입니다. 중요한 기록은 한국천문연구원 또는 공식 달력과 함께 재확인하세요.

## 정적 배포

환경 변수와 빌드 명령이 필요하지 않습니다. 프로젝트 폴더 전체를 그대로 배포합니다.

### GitHub Pages

1. GitHub 저장소에 전체 파일을 올립니다.
2. 저장소 **Settings → Pages**로 이동합니다.
3. 배포 소스를 브랜치의 루트 폴더로 선택합니다.
4. 생성된 Pages 주소에서 `index.html`을 엽니다.

### Netlify

- Netlify Drop에 프로젝트 폴더를 드래그하거나 저장소를 연결합니다.
- Build command: 비워 둠
- Publish directory: 프로젝트 루트

### Vercel

- 저장소를 Import합니다.
- Framework Preset: `Other`
- Build command: 비워 둠
- Output directory: `.` 또는 프로젝트 루트

어떤 배포 방식에서도 외부 날짜 API나 환경 변수가 필요하지 않습니다.
